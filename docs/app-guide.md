# App 接入与使用

## 启动

使用桌面 `VisionLab` 快捷方式。源码入口为 `python -m visionlab.app`，窗口启动器为 `scripts/launch_app.pyw`。依赖列表位于 `requirements.txt`。首次迁移电脑时安装依赖，再运行构建脚本与快捷方式安装脚本。

```powershell
python -m pip install -r requirements.txt
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_shortcut.ps1
```

快捷方式依赖当前工程路径和本机 Python 安装。启动失败会显示错误，并写入 `build/startup-error.log`，运行日志保存在 `build/app.log`。

## 界面布局

界面采用浅灰工作区、白色操作卡片与深色图像视窗。顶部的“实车工作台”和“图像实验室”切换两个模块。实车工作台将连接、接收指标、在线调参与录制分区显示。图像实验室顶部选择数据集与 C 源码，中间并排查看原始输入和算法输出，右侧使用回放、区间选帧和问题导出工具。侧栏支持滚动，时间轴保留红色异常标记与蓝色导出选区。

本次界面改版由你手动验收。关闭并通过桌面快捷方式重新打开 App，检查两个模块和 AI 调试包的字体、对齐与按钮状态。分别在常用窗口大小、最大化及 Windows 125% / 150% 缩放下查看文字换行与图像区域，滚动侧栏确认底部工具可访问。再检查切换 TCP / 串口、选取 C 文件、播放与调速、选中和追加区间、取消异常标记，以及描述问题后导出 ZIP 的流程。

## 实车固件接入

WiFi 连接请选择“WiFi / TCP 服务端”，由电脑监听、小车作为客户端连接。默认监听 `0.0.0.0:8086`，小车的目标地址填写电脑实际 WiFi IPv4。TCP 连接、固件发送条件和由你执行的验收步骤见 [TCP 服务端说明](tcp-server-guide.md)。

当前仓库的 `ASSISTANT_DEBUG_ENABLE` 为 0，USB CDC 底层已由 `debug_init()` 初始化。`USER_USB_CDC=1`，逐飞的 DEBUG_UART 逻辑接口实际经 USB CDC 传输。

在 Keil 的 C251 编译宏定义中启用下面的配置，再用原目标工具链构建。

```text
ASSISTANT_DEBUG_ENABLE=1
ASSISTANT_DEBUG_IMAGE_OVERLAY_ENABLE=0
ASSISTANT_DEBUG_IMAGE_DIV=1
```

总开关启用图像、遥测与参数处理。关闭 overlay 可避免助手在原图里画文字和目标十字。图像分频设为 1 可减少助手主动跳过处理帧的情况，但 USB 带宽和超时仍可能造成传输失败。上述配置本次未写入固件，原始 checkout 的差异为空，C251 构建与实车时序仍待验证。

App 选择 USB 枚举出的 COM 端口，协议选择“逐飞助手（当前固件）”。CDC 波特率字段由驱动接收，原工程若改为物理 UART 则必须匹配固件波特率。若连接后无有效图像，应检查实际烧录版本的总开关和所选接口。

## 调参通道

所有数值均为本地编辑值，连接时不会自动下发，也不会从设备读取默认值。每个“发送”按钮只发送一项参数。当前固件无 ACK 或读参应答，实车显示“已发送，设备协议无 ACK”。本地模拟设备的确认仅用于验证界面流程。

| 通道 | 参数 | 单位与 App 输入范围 |
| --- | --- | --- |
| 1 | 舵机 KP | Q10 原始整数，0～32767 |
| 2 | 舵机 KD | Q10 原始整数，0～32767 |
| 3 | 陀螺仪 KG | Q10 原始整数，-3000～3000 |
| 4 | 电机 KP | Q10 原始整数，0～32767，固件同时写入左右 PI |
| 6 | 最低速度 | 每 15 ms 编码器脉冲，200～700 |
| 7 | 最高速度 | 每 15 ms 编码器脉冲，200～700 |
| 8 | 曝光时间 | 固件原始曝光单位，1～4095 |

App 对通道 1/2/4 采用有界的主机输入范围，固件本身对应分支没有同样的上限。最低/最高速度在固件内部会互相调整，App 没有读回协议，因此两项输入框仍代表本地请求值。原固件通道 5 涉及启动车辆，当前参数面板不包含该通道。

参数包为 8 字节，前四字节依次是 `55 20 channel checksum`，后四字节为小端 IEEE754 float32。checksum 为其余字节之和的低八位，与当前 C251 收包函数的反序处理相匹配。

## 录制与导出

点击开始录制后，后台线程在数据到达时保存原始流，解码出的图像原样写盘。停止、断开和正常关闭 App 都会完成落盘。

```text
capture_.../
  frames.npy
  frame_ids.npy
  metadata.json
  frames.raw
  wire.bin
  telemetry.csv
  events.jsonl
```

`frames.npy` 由原始缓冲区按 uint8、120×188 写成。`frames.raw` 和 `wire.bin` 保留源数据，遥测以 CSV 导出，调参和接收事件保存在 JSONL 中。失败时尽量完成此前完整帧的保存，并将 metadata 标记为 failed。进程被强制终止时，完整 NumPy 文件可能尚未生成，原始文件保留供恢复。

逐飞图像没有 CRC 和设备处理帧号，`frame_ids.npy` 使用主机接收顺序索引，metadata 明确标注 `host_receive_index`、`unverified` 和未知初始化状态。界面接收帧数不能用于推断 MCU 实际处理帧总数。

ZIP 导出包含完整会话，选择会话目录之外的新文件路径。接收预览、遥测 CSV 和原始数据存储分离，界面缩放与绘图仅作用于显示副本。

## 图像实验室

完成录制后点击“送往图像实验室”，再运行 C 算法。已知从视觉初始化开始保留完整历史的数据可以严格回放。真实逐飞片段通常缺少这些条件，须显式选择“允许片段探索”。探索模式允许未知初始化状态、处理帧号缺口和已有参数事件，但每次仍从新进程的初始 C 状态顺序运行现有图像。参数事件暂未重放，视觉避障仍关闭，探索结果只能用于定位线索。

运行完成后可以播放、暂停、逐帧、滑条选择或输入索引。图像跳转仅选择已经顺序计算的结果。异常标记保存为 `annotations.jsonl`。相同数据集连续运行时，界面显示当前帧与上次实验相比有多少行中线变化。

图像算法源码可在其他文件夹修改完成后直接使用。点击“选择 C 文件…”打开系统文件选择器，选择新的视觉 C 模块。标准文件名 `image.c`、`image2.c`、`ring.c`、`visual_avoidance.c`、`laser.c` 会替换对应模块，其他文件名如 `new_image.c` 按实现 `Image_OldStyle_Process()` 的 image 入口处理。完整路径显示在输入框中，“定位文件”会在资源管理器中选中它，“在 VS Code 编辑”打开该文件。

构建优先使用所选入口文件，以及同目录存在的 `image2.c`、`ring.c`、`visual_avoidance.c`、`laser.c` 和配套头文件。缺少的配套模块回退到原工程。文件需要保留当前 C 回放接口与输出数组，图像格式仍为 188×120 uint8。新增硬件依赖或新增编译单元需要相应适配。

点击“构建并回放”，App 会检测选中的源码变化，按需重新编译，再使用同一数据集从初始状态顺序运行。无需重启 App。每个新实验都会保存实际参与构建的 C 文件、依赖头文件、CMake 配置和哈希快照，后续修改源文件不会覆盖旧实验中的代码。

“重新构建 C”可以手动触发编译，“编译输出”显示完整构建日志。编译失败会显示日志窗口，当前已打开的实验结果仍可查看。源码在编译过程中发生变化时，本次构建会报错，保存后再次回放即可。每个实验记录其实际使用的源码和可执行文件哈希。编译错误写入 `build/app-build.log`。

“在 VS Code 调试此帧”打开实验对应的算法文件。在 `Search_line()` 内设置条件断点 `visionlab_frame_index == 当前索引`，F5 后输入数据集、末尾索引、算法文件以及 `strict` 或 `exploratory`。源码级执行使用原有 GDB 配置。

## 播放、时间轴与 AI 调试包

“播放 FPS”可以选择预设速率或输入 0.1～240 的数值，按回车或切换焦点应用。播放逐帧推进已计算结果，目标速率受图像渲染耗时影响。

点击“标记异常帧”后，时间轴相应位置出现红点，再次点击可取消异常标记，并同时移出导出选择，清除该帧的红点和蓝框。点击时间轴红点可以跳转。蓝色方框表示当前选入调试包的帧。标记与选择保存在实验目录的 `review.json`，重新打开实验会恢复，旧版 `annotations.jsonl` 也会读取。

点击图像实验室右侧的“选择帧与导出 AI 调试包”打开调试包面板。可以输入 `12,15,20-24` 这样的帧索引列表，也可以在异常帧列表中用 Ctrl/Shift 多选，或直接选择全部异常标记。填写现象、预期结果和复现观察后，点击底部固定操作区的“导出单文件调试包”。窗口较小时可滚动表单，列表与说明文本各自支持滚动。

面板中的“异常/选定帧索引”列表会随输入实时预览区间。输入 `7-15` 时显示一行 `7-15`、9 帧及对应帧号首尾，即使这些帧尚未单独标为异常也会显示。点击“应用选择”或按回车后保存并同步时间轴；列表还会保留尚未选入的异常标记，支持 Ctrl/Shift 选择多个区间。双击区间可跳转到起始帧。

本次列表修改请手动检查。输入 `7-15` 应立即看到 9 帧；输入 `7-15,20-22` 应看到两个区间、共 12 帧；应用后导出并重新打开实验，选择应保留。输入倒序或越界区间时应显示错误提示，已有保存选择应保留。

主界面的“区间选择”支持直接填写起始帧和结束帧，索引从 0 开始且包含两端。也可以先在时间轴定位起始位置，点击“当前帧设起点”，再定位结束位置并点击“当前帧设终点”。“选中区间”替换当前导出选择，“追加区间”合并到已有选择并自动去重。连续选择在时间轴显示为蓝色区间，并保存到当前实验。

本次区间选择由你手动验收。可先选 10～20，应包含 11 帧；再追加 18～25，总计应为 16 帧。确认导出面板显示 `10-25`，重新打开实验仍保留选择。另检查起止相同只选一帧，以及起点大于终点或超出帧数时报错且原选择保留。

生成的一个 ZIP 包包含以下内容。

```text
ISSUE.md                 AI 分析入口和复现步骤
description.txt          你的文字说明
review.json              异常标记与选帧信息
manifest.json            选中索引、帧号、哈希和历史范围
experiment.json          本次运行的源码、编译器、参数及限制
selected/
  frames.npy             选定帧的逐字节灰度输入
  indices.npy            原实验索引
  frame_ids.npy          对应设备/接收帧号
  c_results.jsonl        完整边线、中线、控制线、阈值和状态
  raw/*.png              同一原始输入的无损灰度 PNG
  overlays/*.png         单独的结果预览
algorithm/               实验当时的源码和依赖快照
replay/
  frames.bin             第 0 帧到选中最后一帧的全部历史输入
  expected.jsonl         对应全部历史 C 输出
  frame_ids.npy
  metadata.json
reproduce.py             独立构建、顺序回放及输出对比脚本
```

完整前置历史用于重现 C 静态变量和状态机。重点分析的帧集中在 `selected/`，原始输入和显示叠加分别保存。将 ZIP 作为附件交给 AI，并让它先阅读 `ISSUE.md`，即可从说明、输入、输出与源码一起定位问题。

旧实验如果没有源码快照，且当前文件已经变化，需要重新构建并回放一次后导出。调试包的代码必须与记录输出对应。旧实验缺失内容、输入损坏或输出被改写时，导出会提示错误。

在安装了 Python、GCC、CMake 和 MinGW Make 的 Windows 上，将包解压到 ASCII 路径后运行 `python reproduce.py`，可重建快照并检查全部历史输出。后续修改快照后可用相同输入观察输出变化。

## CRC 扩展协议

“VisionLab v1（CRC32）”是为后续固件提供的接收适配，当前 STC32 固件尚未发送此协议。模拟设备可生成它以测试断包与校验。该模式中的参数命令沿用上述逐飞 8 字节命令。

固定图像头使用 Python 格式 `<4sBBHII`，依次包含 `VLAB`、版本 1、类型 1、flags、uint32 处理帧号、uint32 载荷长度。载荷固定为 22,560 字节灰度数据，尾部是头与载荷的 CRC32，小端 uint32。flags 的 bit0 表示帧号零之前处于可重现视觉初始状态，其余位保留为零。设备重启或帧号倒退时结束当前录制，另起会话。

CRC 证明接收字节通过传输校验。算法与记录器是否使用同一稳定快照，仍需解决 DMA 库的所有权和实车时序问题。

## 显示清晰度

App 在导入图形库和创建窗口之前声明 Windows Per-Monitor V2 DPI 感知，让系统按屏幕 DPI 原生绘制文字和控件。图像实验室从 188×120 原始像素生成叠加层，查看时采用整数倍最近邻放大，状态文字由 Tk 原生字体绘制。原图与叠加图使用相同的原生图像尺寸。

进程的 DPI 模式需在窗口创建前设置，旧版本窗口需关闭后重新打开桌面快捷方式。当前版本的启动日志会记录 DPI 模式。[Microsoft DPI 文档](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)
