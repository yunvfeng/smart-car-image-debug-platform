# WiFi TCP 服务端与手动验收

## 连接方向

电脑中的 VisionLab 是 TCP Server，小车是 TCP Client。电脑和小车加入能互相访问的网络后，小车主动发起 TCP 连接。

| 设置 | 默认值或填写方式 |
| --- | --- |
| App 连接方式 | WiFi / TCP 服务端 |
| App 监听 IP | 0.0.0.0，监听本机 IPv4 网卡 |
| App 监听端口 | 8086，可修改 |
| 小车的 TCP 目标 IP | 电脑 WiFi 网卡的实际 IPv4 |
| 小车的 TCP 目标端口 | 与 App 监听端口相同 |
| 应用层协议 | 逐飞助手（当前固件），或固件已实现的 VisionLab v1 |

先在 App 点击“开始监听”，再让小车连接。App 会显示监听状态，接受连接后显示客户端地址。一个时刻处理一个客户端，当前连接结束后继续等待下一次连接。

图像、遥测和参数都经过同一个已接受的 TCP 连接。TCP 字节流共用已有的增量协议解析器，处理网络拆包和粘包。重新接受客户端后会重新创建解析器，清空上一连接的半包、待发送命令与预览历史。上一次录制会单独结束，下一次录制生成新的数据目录。

## 固件发送条件

当前仓库的 `wifi_assistant.c` 已包含 TCP 客户端连接代码，目标端口为 8086；`main.c` 当前没有调用这条 WiFi 初始化和连接路径。实际烧录版本需要启用 WiFi，并将服务器目标设置为电脑实际 IP 和监听端口。

如果采用现有逐飞助手协议，固件还需满足以下条件。

- WiFi 模块成功入网，并实际执行 TCP 客户端连接流程。
- 助手总开关 `ASSISTANT_DEBUG_ENABLE=1`。
- 助手接口选择 `ASSISTANT_DEBUG_DEVICE=SEEKFREE_ASSISTANT_WIFI_SPI`。
- 已建立 WiFi 连接后通过该接口发送图像、遥测，并处理接收的参数。
- 原图叠加关闭，`ASSISTANT_DEBUG_IMAGE_OVERLAY_ENABLE=0`。

App 的 TCP 模式沿用之前的图像格式和参数通道。当前逐飞协议没有参数 ACK，显示“已发送”后，需要在车端或图像上观察实际效果。

## 由你执行的验收清单

本次只进行了代码修改与静态阅读，尚未执行运行、连接或实车测试。

### 1. 启动与监听

重开桌面 VisionLab，选择“WiFi / TCP 服务端”，填入 `0.0.0.0` 和 `8086`，协议选择与小车一致。

点击“开始监听”，应显示等待小车连接。此时录制和参数发送处于禁用状态。点击“停止监听”，应能返回未连接状态，再次点击可重新监听。

### 2. 小车连接

让小车以 TCP Client 模式连接电脑的 WiFi IPv4 和端口 8086。App 应显示小车地址，按钮变为“停止监听”，录制和参数发送启用。

如果无法连接，核对电脑实际 IPv4、端口、网络互通情况、小车固件的 WiFi 路径和 Windows 对该应用的入站放行情况。

### 3. 图像与遥测

连续发送至少 30 秒图像。接收帧数、数据量应增长，画面持续刷新，FPS 有读数。若固件发送遥测，相应通道应更新。已有固件连接后的欢迎文本可能被计入解析异常，重点观察有效图像开始后异常是否持续增长。

### 4. 参数回传

先记录当前曝光值，再发送一个便于观察的小幅曝光调整。确认 App 显示发送记录，并在车端或图像亮度上验证生效，再恢复原值。确认命令经当前 TCP 连接到达小车。

### 5. 录制、导出与回放

录制 10 秒后停止保存。检查目录有 `frames.npy`、`frame_ids.npy`、`metadata.json`、`wire.bin`、`telemetry.csv` 和 `events.jsonl`。元数据的 `connection.transport` 应为 `tcp_server`，并保存客户端地址。

导出会话 ZIP，再将数据送入图像实验室，选择合适的回放模式，检查图像、异常标记和 AI 调试包导出。实车片段缺少完整初始化历史时需要“允许片段探索”。

### 6. 断线与重新连接

录制期间主动关闭小车 TCP 连接。应保存此前接收完整的帧，记录结束原因，并恢复等待连接状态。让小车重新发起 TCP 连接，预览和计数应从新连接重新开始，再次录制生成新目录。

Windows 接收连接启用了 TCP keepalive，空闲探测等待为 5 秒、探测间隔为 1 秒。可另外测试小车断电或 WiFi 中断，观察系统检测断开后的保存和重新监听行为。物理链路中断到系统报告断开之间可能有等待时间。[Microsoft keepalive 文档](https://learn.microsoft.com/en-us/windows/win32/winsock/sio-keepalive-vals)

### 7. 端口冲突与模式切换

用另一程序占用相同端口，再尝试监听，应显示错误并恢复可操作状态。停止监听后切换到“串口 / USB CDC”，用本地模拟设备检查原有接收和录制流程，再切回 TCP 模式。
